# Architecture Decision Records

Формат Майкла Найгарда: **Статус, Контекст, Рішення, Наслідки**, плюс розділ
**Альтернативи** з trade-offs. Один ADR на одне рішення. Прийнятий ADR не редагується по суті:
якщо рішення змінюється, пишемо новий ADR зі статусом «Замінює ADR-NNN».

Статуси: `Запропоновано`, `Прийнято`, `Відхилено`, `Застаріло`, `Замінено ADR-NNN`.

## Відповідність номерам PDF

Програма PDP нумерує обовʼязкові ADR по-своєму. Номери тут ідуть у порядку прийняття, тож частина
розійшлась: рішення, яке PDF дає одним ADR, у нас інколи розкладене на кілька, а теми, що
зʼявились у ході роботи (вебхуки, observability), отримали власні номери.
