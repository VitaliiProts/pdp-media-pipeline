# Спайк 02. Переклад відео: розпізнавання, переклад, озвучка

- Дата: 2026-10-17
- Код: [`spikes/02-video-dub`](../../spikes/02-video-dub) (одноразовий, не частина workspace)
- Мета: виміряти час, вартість і зсув фраз до ADR-016, а не вибирати провайдерів за документацією.

## Обраний стек і чому

- Розпізнавання — `gpt-4o-transcribe-diarize` (`diarized_json`: сегменти з `start`, `end`,
  `speaker`). Запасний `gpt-4o-transcribe` на фрагментах між паузами виміряний і відкинутий —
  губить половину тексту; замість нього ретраї й помилка `stt_unavailable` (див. нижче).
- Переклад — LLM OpenAI зі строгою JSON-схемою; вона ж визначає мову оригіналу, бо діаризаційна
  модель мову не повертає.
- Озвучка — Supertonic 3: локально (ONNX, відкриті ваги) за замовчуванням, Supertone API —
  другий адаптер. Окремий пресет-голос на кожного мовця.

Що відомо з документації на 17 жовтня 2026:

- OpenAI вимикає `whisper-1`, `gpt-4o-transcribe` і `gpt-4o-transcribe-diarize`
  26 лютого 2027. Рекомендований `gpt-transcribe` таймкодів не дає, тож інтерфейс
  `SpeechToText` потрібен уже для першої заміни.
- OpenAI вимикає `tts-1`, `tts-1-hd` і `gpt-4o-mini-tts` 6 січня 2027; заміна
  `gpt-realtime-2.1-mini` працює лише через Realtime API. Озвучка на OpenAI не розглядалась.
- Репозиторій Supertonic заархівований (вересень 2026). Ваги на Hugging Face
  (`Supertone/supertonic-3`, OpenRAIL-M: атрибуція й заборона імітувати чужий голос без
  згоди), код прикладів — MIT. Оновлень моделі не буде; це ризик, а не блокер, бо ваги в нас.

## Supertonic 3 локально: що спостерігав

Docker на Apple Silicon (arm64), `--cpus=2 --memory=2g`, `intraOpNumThreads=2`, 8 кроків
дифузії, голоси `M1` і `F1`, шість німецьких фраз від 15 до 157 символів, швидкість 1.0 і 1.3.

| Що                                 | Значення                                     |
| ---------------------------------- | -------------------------------------------- |
| Ваги                               | 407 МБ (з них `vector_estimator.onnx` — 257) |
| Завантаження моделі                | 7.4 с, +432 МіБ RSS                          |
| Пікова пам'ять процесу             | 594 МіБ                                      |
| Швидкість синтезу                  | 0.19–0.37 від тривалості аудіо (RTF)         |
| Час на хвилину мовлення            | 13.5 с (2 CPU, тобто ≈ 27 CPU-секунд)        |
| Темп німецької, швидкість 1.0      | 14.2–14.4 симв./с для звичайних речень       |
| Темп фрази з датою, часом і цінами | 7.7 симв./с                                  |
| Передбачувач тривалості            | 1–5 мс на фразу, похибка до 0.07 с           |
| Частота дискретизації              | 44.1 кГц, моно                               |

Висновки:

- **Тривалість відома до синтезу.** Модель спершу окремою маленькою мережею передбачає
  тривалість, а `speed` її просто ділить; передбачення збігається з фактичною довжиною до
  0.07 с. Тому підгонка не потребує спроб: після перекладу передбачити тривалість усіх фраз за
  мілісекунди, вибрати швидкість під слот (до 1.4), а фрази, яким і 1.4 не досить, одразу
  віддати на коротший переклад — ще до першого синтезу. `atempo` для цього адаптера не потрібен.
- **Бюджет символів — лише перше наближення.** Числа, дати й валюта розгортаються в слова: та
  сама довжина рядка звучить удвічі довше (7.7 проти 14.3 симв./с). Остаточну перевірку робить
  передбачувач, а не лічильник символів; для бюджету в запиті на переклад — 14 симв./с.
- **Ресурси пода.** 2 CPU озвучують хвилину мовлення за ~14 с, а хвилинне відео має менше
  мовлення, ніж хвилину. Під'їдає пам'ять: ~600 МіБ на процес, модель вантажиться 7 с —
  завантажувати один раз при старті пода, а не на задачу. Запит пода `video-dub` — від 1 ГіБ.
- **Alpine не підходить.** `onnxruntime-node` постачає бінарники лише під glibc; в образі
  воркера (`node:22-alpine`) він не завантажується (`ld-linux-aarch64.so.1` відсутній). Для
  `video-dub` потрібен образ на Debian (`bookworm-slim`) — окремий Dockerfile або окрема стадія.
- **Недетермінованість.** Шум дифузії береться з `Math.random`, тож повтор синтезу дає трохи
  інший звук тієї ж тривалості. Для чекпоінтів це не важливо — готовий кліп не синтезується
  вдруге.

Якість на слух (вимова чисел, природність на швидкості 1.3) — у `out/tts/*.wav`; оцінка — після
прослуховування.

## Увесь конвеєр на фейкових провайдерах

Тестове відео — хвилина «Tears of Steel» (0:15–1:15; © Blender Foundation, mango.blender.org,
CC BY 3.0; саундтрек — CC BY-ND 3.0, тож результати дубляжу не публікуються й не комітяться):
суперечка двох героїв під музику, голос робота, ще одна репліка — 11 фраз, 4 мовці.

- Розпізнавання — фейк з англійських субтитрів фільму, мовці розмічені вручну. Таймінг субтитрів
  трохи ширший за мовлення, для таймлайну цього досить.
- Переклад — фейк з німецьких субтитрів фільму: людський переклад, але для читання, а не для
  дубляжу; скорочувати на запит він не вміє.
- Озвучка, підгонка, зведення, монтаж і VTT — справжні.

```bash
cd spikes/02-video-dub
docker build -t pdp-spike-dub .        # Debian + ffmpeg 5.1 — форма образу для video-dub
docker run --rm -v "$PWD":/w -w /w --entrypoint sh pdp/video-worker:dev -c \
  'ffmpeg -ss 15 -t 60 -i https://download.blender.org/demo/movies/ToS/tears_of_steel_720p.mov \
   -c:v libx264 -preset veryfast -crf 23 -c:a aac -b:a 160k input/tos-1min.mp4'
curl -s -o input/TOS-en.srt https://download.blender.org/demo/movies/ToS/subtitles/TOS-en.srt
curl -s -o input/TOS-de.srt https://download.blender.org/demo/movies/ToS/subtitles/TOS-de.srt
docker run --rm --cpus=2 --memory=2g -e VOICES=F1,M1,M2,F2 -v "$PWD":/spike pdp-spike-dub \
  node dub.mjs
```

Перемикачі: `STT=fake|diarize|chunked`, `TRANSLATOR=fake|fixture|openai`,
`BACKGROUND=separated|ducked` (`SEPARATED` — шлях до фону), `FULLNESS`, `MODEL`, `VOICES`,
`THREADS`. Таблиця нижче — перший прогін: закадровий голос (`ducked`) і субтитровий переклад.
Платні кроки кешуються в `out/…/*.json`, як чекпоінти процесора; `FRESH=1` їх ігнорує.

Що спостерігав (2 CPU):

| Крок                        | Час                       |
| --------------------------- | ------------------------- |
| Завантаження моделі         | 5–7 с (раз на под)        |
| Витяг аудіо (FLAC 16 кГц)   | 0.15 с, 2.1 МБ на хвилину |
| Передбачення тривалості, 11 | 52 мс                     |
| Озвучка, 528 символів       | 8 с                       |
| Зведення з приглушенням     | 1 с                       |
| Монтаж без перекодування    | 0.2 с                     |

- **Своя частина конвеєра — близько 10 с на хвилину відео** на 2 CPU. Решта часу — мережеві
  виклики розпізнавання й перекладу; їх доміряю з ключем.
- **Скорочення перекладу — не крайній випадок, а основний шлях.** Субтитровий переклад довший за
  мовлення: 5 з 11 фраз не влазять у свій слот навіть на швидкості 1.4, 9 з 11 прискорені. Без
  скорочення зсув накопичується у швидкому діалозі, де фрази йдуть впритул: до 5 с, 7 фраз
  починаються пізніше ніж на 0.5 с. Критерій етапу (≈ 0.5 с) тримається лише на LLM, що пише
  коротко з самого початку й скорочує на запит.
- **Передбачувач у конвеєрі** помиляється на 0.00–0.06 с проти фактичної довжини кліпу.
- **Голос за чергою мовців не знає статі:** Селія отримала чоловічий `M1`, Том — жіночий `F1`.
  Висота голосу не працює, класифікатор статі — працює; див. «Стать мовця» нижче.
- **Вихідний MP4** — відео без перекодування, `deu` за замовчуванням, `eng` другою, VTT за
  фактичними позиціями фраз. ffmpeg 5.1 з Debian має все потрібне (`sidechaincompress`,
  `amix normalize=0`).
- **Хвилина — ліміт дубляжу** (рішення 17.10): усе аудіо йде в розпізнавання одним запитом, без
  нарізки на шматки.

## Справжній дубляж: оригінальний голос прибраний (Demucs)

Закадровий голос з приглушеним оригіналом звучить як багатоголосий переклад, а потрібен дубляж:
оригінального голосу не чути зовсім, музика й ефекти лишаються. Для цього аудіо розділяється на
голос і фон, і німецький голос зводиться з фоном (`BACKGROUND=separated`, без приглушення).

```bash
docker build -t pdp-spike-separate separate   # python 3.11, torch 2.5.1 CPU, demucs 4.0.1
ffmpeg -i input/tos-1min.mp4 -ac 2 -ar 44100 -c:a pcm_s16le input/orig.wav
docker run --rm --cpus=2 --memory=4g -e TORCH_HOME=/spike/out/torch -v "$PWD":/spike \
  pdp-spike-separate demucs -n htdemucs --two-stems=vocals -j 1 -o out/sep input/orig.wav
docker run --rm -v "$PWD":/spike pdp-spike-separate python separate/compare.py htdemucs
```

Еталон — студійна доріжка «музика й ефекти без діалогів» з сайту Blender
(`TOS_MUSIC+FX_NO_DIALOGUE.aif`, той самий відрізок). Студійний стерео-мікс збігається з аудіо
фільму з кореляцією 0.97 при зсуві 25 мс, тож порівнювати можна.

| Модель        | Хвилина аудіо, 2 CPU                 | Пам'ять |
| ------------- | ------------------------------------ | ------- |
| `htdemucs`    | 73 с (78 з першим завантаженням ваг) | 1.5 ГіБ |
| `htdemucs_ft` | 4 хв 55 с                            | 2.2 ГіБ |

Образ із PyTorch CPU — 1.64 ГБ.

Рівень фону по відрізках (дБ RMS): під час діалогу аудіо фільму −18…−22, студійний фон
−33…−49, фон від `htdemucs` −30…−46 — у межах ~3 дБ від студійного, тобто голос придушений на
15–25 дБ. Залишок (оцінка мінус студійний фон) на 13 дБ тихіший за діалог; частина цього
залишку — різниця між фінальним міксом фільму й студійною доріжкою, а не голос. `htdemucs_ft`
на цьому кліпі помітно не кращий, а вчетверо повільніший. SI-SDR по всьому кліпу тут не
показовий: під час діалогу музика на 15–25 дБ тихіша за голос, і метрику визначають гучні
відрізки, де фінальний мікс відрізняється від студійної доріжки.

Висновки:

- **Розділення — найдорожчий крок конвеєра:** 73 с CPU на хвилину проти ~10 с на все інше
  нашої частини. Воно не залежить від розпізнавання й перекладу, тож може йти паралельно з
  платними викликами й частково ховатися за ними.
- **Python і PyTorch у конвеєрі.** Розглядались CLI `demucs` в образі `video-dub` (як ffmpeg,
  образ ~2 ГБ), Python-контейнер поруч у тому ж поді, порт у ONNX для `onnxruntime-node` і
  окремий сервіс. **Рішення (17.10): окремий сервіс `audio-separate`** зі своїм Deployment і
  масштабуванням — розділення в рази дорожче за решту, а под `video-dub` здебільшого чекає на
  API, тож ресурси під них різні. Обґрунтування й протокол — в ADR-016.
- **Еталон для слуху** — `out/dub-fake-fixture-studio/` (студійний фон): різниця з
  `out/dub-fake-fixture-separated/` — це те, що втрачає Demucs.

## Переклад під тривалість: варіанти й передбачувач

Замість одного перекладу, який потім стискається, перекладач отримує тривалість кожної фрази
(`seconds`) і повертає три варіанти від повного до найкоротшого. Передбачувач Supertonic оцінює
кожен варіант за мілісекунди, і `chooseVariant` бере той, що найближчий до оригінальної
тривалості з найменшим прискоренням; кожен крок скорочення коштує 0.3 с розбіжності
(`FULLNESS`), щоб не викидати зміст заради десятих секунди.

Без ключа варіанти написані вручну (`fixtures/tos-de-variants.json`, `TRANSLATOR=fixture`) у
стилі, якого просимо від LLM, і без вимірювання тривалостей. Той самий формат повертає
`providers/openai.mjs`.

| Переклад                         | Прискорено | Пізніше 0.5 с | Макс. зсув |
| -------------------------------- | ---------- | ------------- | ---------- |
| Субтитри (один варіант)          | 9 з 11     | 7             | 5.04 с     |
| Варіанти, без переваги повнішого | 4          | 0             | 0.48 с     |
| Варіанти, `FULLNESS=0.3`         | 5          | 0             | 0.48 с     |

- **Підбір прибирає накопичення зсуву.** Критерій етапу (≈ 0.5 с) виконується вже на цьому
  кліпі, і саме в найшвидшому діалозі.
- **Без переваги повнішого** алгоритм охоче бере найкоротший варіант («Blödmann!» замість «Du
  bist ein Idiot, Thom.»). З `FULLNESS=0.3` повні варіанти повертаються там, де синхрон від
  цього не страждає (фрази 1 і 11). 0.6 вже змушує прискорювати сильніше.
- **Фраза 8** («...by these giant robotic claws of death...», слот 1.2 с) не влазить жодним
  варіантом — тут потрібен запит на коротший переклад; фейк його не вміє, тож вона прискорена до
  1.4 і заходить на 0.4 с у паузу.
- Що, якщо жоден варіант не влазить: береться той, що перевищує найменше, а не найповніший.

## Справжні OpenAI: розпізнавання й переклад

```bash
echo 'OPENAI_API_KEY=…' > .env   # у .gitignore
docker run --rm --cpus=2 --memory=2g -e STT=diarize -e TRANSLATOR=openai -e REASONING=minimal \
  -e VOICES=F1,M1,M2,F2 -v "$PWD":/spike pdp-spike-dub node dub.mjs
```

Додаткові перемикачі: `REASONING` (`reasoning_effort` перекладача), `STT_SOURCE` (що
розпізнавати, наприклад `out/sep/htdemucs/orig/vocals.wav`), `NOISE_DB` і `MIN_SILENCE` (нарізка
за тишею для `STT=chunked`).

### Розпізнавання

Повнота — частка слів субтитрів (76 слів), знайдених у транскрипті:

| Варіант                                     | Сегментів | Повнота | Мовці                   |
| ------------------------------------------- | --------- | ------- | ----------------------- |
| `diarize`, мікс фільму                      | 7         | 0.87    | 3; робот записаний Тому |
| `diarize`, відділений голос                 | 7         | 0.86    | 3; робот записаний Тому |
| `chunked`, мікс (−30 дБ, пауза 0.4 с)       | 2         | 0.33    | 1                       |
| `chunked`, відділений голос (−30 дБ, 0.4 с) | 6         | 0.24    | 1                       |
| `chunked`, відділений голос (−35 дБ, 0.2 с) | 9         | 0.49    | 1                       |

- **Діаризація працює.** Селію й Тома розділено правильно в обох варіантах, синтезований голос
  робота дістався Тому (для дубляжу — його голосом), науковець окремо. Сегменти — репліки
  одного мовця підряд: 1–6 с, сусідні субтитри одного мовця злиті («Look Celia… / …you have
  your robotics…» — один сегмент 5.8 с). Пауза всередині такого сегмента губиться, але зсув від
  цього не росте. Межі точніші за субтитри (субтитри з'являються раніше за мовлення на 0.5–1 с).
- **Помилки розпізнавання.** На міксі пропущена перша репліка «You're a jerk, Thom.» під
  музикою, «Whatever, Thom. We're done.» стала «We're done! We're done!». На відділеному голосі
  перша репліка є, але почута як «I jerked off.», і LLM чесно переклав це вульгарно. Помилка
  розпізнавання може дати образливий дубляж — аргумент за ендпоінт транскрипту, щоб людина
  бачила, що саме розпізнано.
- **Відділений голос не дає виграшу** в повноті, а ставить розділення (73 с) на критичний
  шлях перед розпізнаванням. Розпізнаємо мікс паралельно з розділенням.
- **Запасний `gpt-4o-transcribe` без міток часу непридатний** як автоматичний фолбек: на
  шматках з кількома репліками модель повертає одну-дві фрази й губить решту (повнота
  0.24–0.49), на коротких шматках вигадує («わ。», «Wir dann!»). Дрібніша нарізка допомагає лише
  частково. **Рішення (17.10):** фолбеку на іншу модель немає — при недоступності діаризації
  ретраї з backoff, далі помилка задачі з кодом `stt_unavailable`, а не тихий дубляж половини
  тексту. `STT=chunked` лишається в спайку лише як виміряний варіант.
- **Ліміт моделі — 2000 вихідних токенів на запит**, а хвилина діалогу з'їла 954 (JSON із
  сегментами). Для ліміту в хвилину запас є, для довших відео знадобиться нарізка.
- **Мову повертає перекладач** (`sourceLanguage: "en"`), як і планувалось.

### Переклад (`gpt-5-mini`)

| `reasoning_effort` | Час   | Токени (вхід / вихід) | Вартість |
| ------------------ | ----- | --------------------- | -------- |
| за замовчуванням   | 26 с  | 418 / 3742            | $0.0076  |
| `minimal`          | 3.7 с | 432 / 377             | $0.0009  |

- **`minimal` — у 7 разів швидше й у 8 разів дешевше**, а переклад не гірший: на
  замовчуванні модель переписала «ми мусимо йти за своїми пристрастями» як «Folge deiner
  Leidenschaft» і дала варіанти не за спаданням довжини. З уточненим промптом («кожен
  наступний помітно коротший, зміст не змінювати») і `minimal` обидва дефекти зникли; окремо
  внесок промпту не міряв.
- **Зсув:** макс. 0.08 с на міксі (0 фраз пізніше 0.5 с), 0.25 с на відділеному голосі —
  краще за ручні варіанти (0.48 с), бо діаризація дає довші сегменти зі слотами, а LLM пише під
  `seconds`.
- **Запит на коротший переклад** знадобився 1 раз з 7 (фраза 1.05 с). Перша версія ділила
  системний промпт із перекладом, і модель повернула в `text` нумерований список із трьох
  варіантів — його озвучило на 7 с і зсунуло все на 4 с. Тепер у скорочення свій промпт, а
  результат приймається, лише якщо передбачувач каже, що він коротший.

### Тиша в кліпах Supertonic

На слух дубляж відставав від акторів, хоча звіт показував зсув 0.08 с. Звіт міряє позицію
кліпу, а не початок голосу в ньому: кожен кліп Supertonic має 0.4–0.6 с тиші на початку й
0.4–0.8 с у кінці (на швидкості 1.0; з прискоренням тиша стискається разом із мовленням), і
передбачувач рахує її в тривалість. Звідси дві вади: голос починався на ~0.5 с пізніше за
позицію, і фраза здавалась на ~1.25 с довшою — зайве прискорення й коротші варіанти.

Тепер адаптер обрізає тишу з обох боків (вікна 10 мс тихіші за −30 дБ від піку, з запасом
30 мс), а `predict` віднімає 1.25 с. Початки німецьких фраз у `voice.wav` збігаються з
позиціями до 0.03 с; передбачувач помиляється на ±0.2 с (тиша варіює). Відносно голосу акторів
(онсети у відділеному голосі) дубляж тепер починається на 0.1–0.3 с раніше — мітки діаризації
стоять трохи перед голосом. Прискорених фраз стало 2 замість 3, і обрані повніші варіанти.
Результати на фейках і ручних варіантах вище виміряні ще з тишею: реальне відставання там на
~0.5 с більше за таблиці, а `CHARS_PER_SECOND` занижене.

### Фрази за часом слів (примусове вирівнювання)

Діаризація повертає репліку на кожну зміну мовця: кілька речень злиті в сегмент 5–6 с, а його
межі на 0.1–0.6 с ширші за голос. Німецький текст заповнював сегмент суцільно, зі своїми
паузами, — на слух розсинхрон усередині реплік. Паузи між реченнями в швидкому діалозі —
100–200 мс, за енергією голосу їх не відрізнити від пауз між словами, і тексту вони не дають.

Тому кожне слово транскрипту отримує час примусовим вирівнюванням: `separate/align.py`
(torchaudio `MMS_FA`, wav2vec2, модель 1.18 ГБ) вирівнює текст сегмента в його вікні ±0.5 с.
`lib/phrases.mjs` ріже репліки на фрази на кінцях речень і паузах від 0.35 с (одне слово не
лишається саме), кожна фраза має час своїх слів. Перекладач бачить фрази з одним `turn` як
частини однієї репліки й тримає зміст кожної частини в її часі. Фраза ставиться на початок
своїх слів і цілиться закінчитись разом з оригіналом: швидкість 0.9–1.4.

```bash
docker run --rm --cpus=2 --memory=4g -e TORCH_HOME=/spike/out/torch -v "$PWD":/spike -w /spike \
  pdp-spike-separate python separate/align.py out/sep/htdemucs/orig/vocals.wav \
  out/dub-aligned-vocals/transcript.json out/dub-aligned-vocals/words-vocals.json
docker run … -e WORDS=out/dub-aligned-vocals/words-vocals.json … node dub.mjs
```

| Варіант                       | Фраз | Початок, сер. / макс. | Кінець, сер. / макс. |
| ----------------------------- | ---- | --------------------- | -------------------- |
| Сегменти діаризації           | 7    | 0.24 / 0.57 с         | —                    |
| Фрази, вирівнювання на міксі  | 11   | 0.01 / 0.08 с         | 0.23 / 0.64 с        |
| Фрази, вирівнювання на голосі | 11   | 0.01 / 0.08 с         | 0.20 / 0.90 с        |

(Початок для сегментів діаризації — розбіжність їхніх міток із першим словом за вирівнюванням.)

- **8 з 11 фраз на голосі закінчуються в межах 0.1 с від оригіналу.** Решта: фраза 4
  перекривається з наступною реплікою (на 0.9 с раніше), дві короткі фрази коротші навіть на
  0.9. Найбільша розбіжність діаризації — «Why don't you…» на 0.57 с раніше за голос.
- **Вирівнювання на міксі** збігається з голосом до 20 мс у 90% слів, але там, де текст
  розпізнано неправильно («Whatever, Thom» → «We're done!»), слово розтягується через паузу з
  музикою на 1.2 с. На відділеному голосі пауза видна, тож вирівнюємо голос.
- **Час і ресурси:** 25 с на хвилину (2 CPU), модель вантажиться ~10 с, ваги 1.18 ГБ; пам'ять
  ще не міряна.
  Вирівнювання йде після розділення (на голосі) і перед перекладом: критичний шлях
  розділення 73 с → вирівнювання 25 с → переклад 5 с → озвучка 8 с, ≈ 2 хв на хвилину відео.
  Розпізнавання йде паралельно з розділенням.
- **Для ADR-016:** вирівнювання — той самий Python/PyTorch, що й Demucs, тож це другий крок
  сервісу `audio-separate` (голос + фон + час слів), а не новий сервіс. `MMS_FA` знає лише
  латиницю: для кирилиці (українська як мова оригіналу) потрібна романізація (`uroman`) —
  перевірити до реалізації. Ваги `MMS_FA` — CC BY-NC 4.0: для PDP прийнятно, для комерційного
  запуску потрібна заміна (ADR-016).
- Пропущена розпізнаванням репліка («You're a jerk, Thom.», 0:08) лишається без дубляжу —
  вирівнювання не відновлює текст, якого немає.
- **Пошук пропусків:** інтервали голосу у відділеній доріжці без жодного вирівняного слова
  (≥ 0.5 с) знаходять рівно цю репліку (8.28–9.49). Окреме розпізнавання шматка
  `gpt-4o-transcribe` нестабільне: без промпту «Jerkdom!», «I jerked them.», з текстом сусідньої
  репліки «You're a jerk, Dom!», «Jerkdom»; правильно — лише з іменами в промпті, яких конвеєр не
  знає. Тому пропуск — сигнал для ендпоінту транскрипту («нерозпізнаний фрагмент 0:08–0:09»), а
  не автоматична вставка в дубляж.

### Стать мовця

З діаризацією першим заговорив Том, і голоси за чергою дали йому жіночий `F1`, а Селії —
чоловічий `M1`: на слух — найбільша розбіжність із відео.

- **Висота голосу (F0) не працює.** Автокореляція по фразах відділеного голосу правильно міряє
  синтетичні голоси (F1 182 Гц, M1 134, M2 93), але Том у цій сцені кричить: один горб
  160–300 Гц, медіана 242 Гц — вище будь-якого порогу між чоловічим і жіночим. Селія — 291 Гц,
  науковець — 101 Гц. Подвоєння октави немає, це справді висота крику.
- **Класифікатор статі за тембром** — `separate/gender.py`, wav2vec2
  (`alefiury/wav2vec2-large-xlsr-53-gender-recognition-librispeech`, 0.3B, LibriSpeech),
  шматки до 5 с по репліках з вирівнювання, ймовірності усереднені по мовцю з вагою тривалості.
  Результат: Том — чоловік (0.59), Селія — жінка (0.001), науковець — чоловік (0.999); голоси
  `M1`, `F1`, `M2`. Але по репліках Том нестабільний: спокійна 0.99, дві з криком — 0.001.
  Правильну відповідь дає лише агрегування по мовцю; для мовця з однією крикливою реплікою
  стать буде хибна.
- **Час:** модель вантажиться ~24 с (з першим завантаженням), класифікація 26 с на 23 с мовлення
  (2 CPU) — дорожче, ніж треба; можна брати лише кілька найдовших шматків на мовця.
- **Для ADR-016:** стать — третій крок `audio-separate` (голос + фон, час слів, стать мовців).
  Користувач має змогу змінити голос мовця в UI (класифікатор помиляється на крику). Ліцензія
  моделі — Apache 2.0.

30-секундне вікно за субтитрами з Wikimedia Commons: 10 реплік, 92 слова, мовлення 29.3 с із 30,
4–5 підлітків обох статей. Медіа не комітиться.


| ------------------------------------ | ---- |
| Demucs (паралельно з розпізнаванням) | 42 с |
| Розпізнавання `diarize`              | 15 с |
| Вирівнювання слів                    | 27 с |

- **Синхрон тримається:** 11 фраз, усі починаються з оригіналом (макс. 0.08 с); кінець — сер.
  0.21 с, 9 з 11 у межах 0.35 с, найбільше −0.76 с («Yeah, and get wasted…» — німецька коротша
  навіть на 0.9).

  a», «Get it?» пропущене — переклад лишив англійські «fun guys», каламбур втрачено.
- **Діаризація зливає мовців:** 2 мовці на 4–5 людей. Класифікатор по репліках це показує:
  у мовця A репліка 1 — чоловік (0.997), репліка 3 — жінка (0.999); у B усі репліки жіночі,
  зокрема «Relax, sugar buns» (за сюжетом — дівчина до свого хлопця). Агрегування по мовцю дає
  A чоловічий голос, тож репліка 3 звучить чоловічим. На першому відео навпаки: різкі розбіжності
  по репліках означали крик того самого чоловіка. Один класифікатор статі ці випадки не
  розрізняє — потрібні ембединги мовця (порівняння голосу реплік, наприклад ECAPA) як перевірка
  діаризації, або ручне виправлення мовців у UI. Відкрите питання для ADR-016.
- **Вартість 30 с:** розпізнавання $0.0096 (857 вихідних токенів — JSON сегментів дорожчий за
  аудіо), переклад $0.0011. У перерахунку ≈ $0.02 за хвилину густого діалогу.
- **Голоси:** у Supertonic 3 по 5 пресетів на стать (`M1`–`M5`, `F1`–`F5`), спайк завантажив і
  прослухав лише чотири. Дитячих голосів немає.

### Українська як мова дубляжу

Supertonic 3 говорить українською (`uk` серед 31 мови), тег доріжки `ukr`. Обидва кліпи —
`TARGET=uk` з тими ж транскриптом, часом слів і статтю (`out/sf-uk-low/`, `out/tos-uk-low/`).

На відміну від німецької, українська позначає рід у минулому часі, прикметниках і звертаннях —
перший прогін дав «Я не **налякана**» від Тома, «Я **думав**» від дівчини, «**солоденька**» до
хлопця. Перекладач не знав статі. Тепер кожна фраза йде з `speakerGender` і `listenerGender`
(стать найближчого іншого мовця — найімовірнішого адресата), а промпт вимагає узгоджувати рід,
звертання й пестливі слова. З `minimal` свій рід правильний, а рід адресата — через раз
(«солоденька», «злякалася» до Тома); з `reasoning_effort: low` — правильно в усіх випадках
(«мій маленький цукерко», «ти… наляканий»), і зміст точніший («We're done» → «Все, між нами
кінець!» замість «Ми закінчили!»).

Інші знахідки й виправлення:

- **Примітки в тексті для озвучки:** «уб’ю її (жарг.)», «fun guys (гриби)», керівний символ
  замість апострофа. Промпт: лише слова для вимови, без приміток і пояснень каламбурів;
  керівні символи вичищаються перед синтезом.
- **Пом'якшення:** «I swear I'm gonna kill her» → «то вмру від терпіння». Промпт: лайка,
  погрози й сленг не пом'якшуються.
- **Підгонка замість скорочення.** Ліміт `maxChars` розрахований на німецьку (14 символів/с), а
  українські слова довші: два повні варіанти не влазили, третій урізаний — розрив 2 с. Тепер
  для фраз, що після вибору варіанта розходяться з оригіналом більше ніж на 0.5 с (не влазять або
  закінчуються зарано), LLM переписує повний варіант під кількість слів (швидкість мовлення
  голосу цією мовою — з передбачувача), дає три довжини навколо цілі, а передбачувач бере
  найкращу. Точну кількість символів модель не тримає, слова — тримає. Сусідні частини тієї ж
  репліки йдуть як контекст — інакше «і заблокований» не узгоджується з «пам'ять». Запити
  паралельні.

## Перевірки до реалізації (18.10)

Після ADR-016, перед кодом 5d.1. Мови дубляжу в UI (рішення 18.10): **українська, німецька,
англійська, іспанська, французька**.

### Потоки PyTorch під лімітом CPU

У контейнері з `--cpus=2` PyTorch бачить усі 12 ядер хоста і запускає 12 потоків, які душать один
одного квотою CFS. Через це всі виміри Python-кроків вище завищені. З `OMP_NUM_THREADS=2`:

| Крок (хвилина аудіо, 2 CPU) | 12 потоків | 2 потоки |
| --------------------------- | ---------- | -------- |
| Розділення Demucs           | 73–97 с    | 41 с     |
| Вирівнювання слів           | 25 с       | 9 с      |
| Стать, 3 шматки на мовця    | 19–20 с    | 6 с      |

Кількість потоків у поді `audio-separate` має дорівнювати ліміту CPU (`OMP_NUM_THREADS`, або
`torch.set_num_threads` зі значення cgroup). Критичний шлях хвилини відео тепер: розділення
41 с → вирівнювання 9 с → стать 6 с → переклад 8–27 с → підгонка 4–11 с → озвучка 8 с →
зведення 1 с, **≈ 1.5 хв**, а не 2. Розпізнавання (15 с) ховається за розділенням. Переклад з `low` —
найнестабільніший крок: та сама задача займала 8 с іспанською й 27 с французькою.

### Пам'ять `audio-separate`

`separate/service_check.py`: усі три моделі в одному процесі, дві задачі підряд (хвилина Tears
of Steel, 30 с Sprite Fright), RSS після кожного кроку:

| Після                  | RSS      | Пік      |
| ---------------------- | -------- | -------- |
| Завантаження Demucs    | 395 МіБ  | 462 МіБ  |
| + `MMS_FA` і `uroman`  | 1646 МіБ | 2796 МіБ |
| + класифікатор статі   | 1713 МіБ | 2796 МіБ |
| Перша задача (хвилина) | 3648 МіБ | 3648 МіБ |
| Друга задача (30 с)    | 3611 МіБ | 3994 МіБ |

Моделі вантажаться ~6 с (з локального кешу). Пік ~4 ГіБ, тож requests `4Gi`, limits `5Gi`.

### Стать за трьома найдовшими шматками

На обох кліпах три найдовші шматки на мовця дають ту саму стать для всіх мовців, що й усе
мовлення (Том 0.63 замість 0.59, решта однакова), а 8.5 с скорочуються до 6. Коротші шматки (2–3 с)
часу майже не економлять, а два шматки по 3 с уже переводять Тома в жінки (0.50). Беремо
**3 шматки до 5 с**: межа часу на кліпах із багатьма репліками.

### Кирилиця: `uroman` + `MMS_FA`

`separate/check_align.py` вирівнює вже готовий дубляж, де місце кожної фрази в `voice.wav`
відоме точно: фрази однієї репліки йдуть одним сегментом, ширшим на 0.3 с з кожного боку, як від
діаризації. Похибка — між першим і останнім словом фрази та її справжніми межами.

| Дубляж             | Романізація | Невирівняні слова | Старт, сер. / макс. | Кінець, сер. / макс. | Межі до 0.1 с |
| ------------------ | ----------- | ----------------- | ------------------- | -------------------- | ------------- |
| Tears of Steel, uk | ні          | 60 з 61           | —                   | —                    | 0 з 2         |
| Tears of Steel, uk | `uroman`    | 2 з 61            | 0.04 / 0.10 с       | 0.12 / 0.68 с        | 17 з 22       |
| Sprite Fright, uk  | `uroman`    | 2 з 73            | 0.10 / 0.66 с       | 0.08 / 0.18 с        | 16 з 22       |
| Tears of Steel, de | ні          | 1 з 75            | 0.07 / 0.48 с       | 0.05 / 0.12 с        | 20 з 22       |
| Sprite Fright, de  | ні          | 0 з 77            | 0.04 / 0.07 с       | 0.08 / 0.26 с        | 20 з 22       |
| Sprite Fright, de  | `uroman`    | 0 з 77            | 0.04 / 0.07 с       | 0.06 / 0.13 с        | 21 з 22       |

- **Кирилиця працює.** Без романізації не вирівнюється жодне українське слово; з `uroman` —
  трохи гірше за німецьку, але в межах критерію етапу.
- **Романізація — завжди**, а не лише для кирилиці: вона ж розгортає діакритику («ü» → «ue»,
  «é» → «e»), яку раніше просто викидали, і німецька стала точнішою.
- **Викиди** — не кирилиця, а дві відомі вади `MMS_FA`: останнє слово репліки розтягується в
  тишу розширеного вікна («рукою?» 1.1 с замість ~0.4), а вигук без голосних («Тс-с!») нема на що
  спертися.
- **Наскрізно:** український дубляж Sprite Fright як оригінал (`input/sf-uk-src.mp4`) —
  справжнє розпізнавання української, вирівнювання з `uroman` на його тексті й на голосі після
  Demucs. Межі реплік за 0.01–0.13 с від справжніх (одна — 0.29 с), хоча розпізнавання помилялось.

### Розпізнавання української

На синтетичному українському голосі `gpt-4o-transcribe-diarize` помиляється помітно частіше, ніж
на англійських акторах: «екофанатка» → «кофемашина», «попереду» → «попереджу», «Не барімося» →
«Бавимося», англійські вставки — фонетично кирилицею («Fun Guys and a» → «Пан Гайс енд Ар»),
«Тс-с!» пропущене. Діаризація й стать правильні. Голос синтетичний, тож це не оцінка на живих
акторах, але аргумент за транскрипт поруч із програвачем: переклад сумлінно передає помилку
(«coffee machine»).

### Голоси й темп п'яти мов

`voices.mjs`: 10 голосів × 5 мов × 3 фрази (звичайна, з часом доби, емоційна) — `out/voices/
{мова}.wav` для прослуховування, позиції голосів у `{мова}.txt`. Темп після обрізання тиші:

| Мова | Симв./с | Найповільніший / найшвидший голос | Слів/с | Похибка передбачувача, макс. |
| ---- | ------- | --------------------------------- | ------ | ---------------------------- |
| uk   | 16.2    | 14.6 / 18.8                       | 2.70   | 0.28 с                       |
| de   | 19.4    | 17.1 / 22.6                       | 3.51   | 0.26 с                       |
| en   | 20.2    | 17.8 / 23.1                       | 3.77   | 0.47 с                       |
| es   | 20.0    | 17.1 / 23.1                       | 3.58   | 0.45 с                       |
| fr   | 21.8    | 18.8 / 25.6                       | 4.28   | 0.20 с                       |

- **Бюджет символів залежить від мови й голосу** — розкид між голосами ~30%, між мовами ~35%.
  Сталі 14 симв./с (німецька з тишею) занижують бюджет для всіх мов. `maxChars` рахувати з темпу
  обраного голосу цією мовою (передбачувач на калібрувальній фразі при старті пода), остаточно
  вирішує передбачувач, як і раніше.
- **Похибка передбачувача до 0.47 с** — стала поправка на тишу (1.25 с) не для всіх голосів і мов
  точна. Поправку варто калібрувати на голос і мову тим самим прогоном.
- У пули йдуть усі десять голосів (рішення 18.10).

### Іспанська, французька, англійська в конвеєрі

Sprite Fright іспанською й французькою з тим самим розпізнаванням, часом слів і статтю; англійська —
з українського оригіналу вище. `reasoning_effort: low`.

| Дубляж               | Старт, макс. | Кінець, сер. / макс. | Підігнано | Переклад |
| -------------------- | ------------ | -------------------- | --------- | -------- |
| Sprite Fright, es    | 0.08 с       | 0.12 / 0.25 с        | 1 з 11    | 8–9 с    |
| Sprite Fright, fr    | 0.08 с       | 0.13 / 0.35 с        | 1 з 11    | 27 с     |
| Sprite Fright, uk→en | 0.02 с       | 0.17 / 0.44 с        | 1 з 10    | 8–12 с   |

- **Синхрон — як в українській і німецькій.** Рід мовця й адресата правильний: «mi bombón»,
  «mon petit chou» до хлопця, «tombés» у чоловічій множині.
- **Підгонка вигадувала зміст**, коли фразу треба було подовжити: «Relax, my little candy, I'll
  handle this», «Vamos, equipo, vamos». Промпт підгонки: довший варіант каже те саме повніше,
  без нових тверджень, прохань і повторів. Після правки — «Relax, my little sugar, darling»,
  «Relájate, cariño, cálmate».
- **Рід групи не виводиться з тексту.** Дівчина про змішану компанію: «we'll have all the fun»
  → «nosotras nos divertiremos» (жіноча множина) — і з правилом «рід мовця стосується лише "я"»,
  і з явним прикладом «nosotros». Без відео модель вирішує, що «ми» — дівчата. Відоме обмеження;
  лікується лише правкою перекладу людиною.
- **Примітка в тексті повернулась** один раз з п'яти прогонів: «'fun guys' literal». Правило
  `SPOKEN_ONLY` потрібне, але не гарантоване — у продукті варто вичищати лапки й дужки й
  позначати такі фрази.

### Конвеєр 5d на справжніх провайдерах (19.10)

Compose-стек з `DUB_PROVIDERS=openai` і `audio-separate` по HTTP, хвилина Tears of Steel
(`input/tos-1min.mp4`) через API. Українська — повний прогін; виправлення мовця, німецька,
іспанська й французька — `reuseOf` першого; англійська — з виправленого українського дубляжу як
оригіналу (мову визначено як `uk`). Час — від створення задачі до `succeeded`.

| Дубляж              | Час   | Старт, макс. | Кінець, сер. | Прискорено / підігнано / не влізло |
| ------------------- | ----- | ------------ | ------------ | ---------------------------------- |
| uk                  | 102 с | 0.01 с       | 0.13 с       | 3 / 2 / 0 з 10                     |
| uk, Том виправлений | 40 с  | 0            | 0.28 с       | 6 / 2 / 0 з 10                     |
| de                  | 35 с  | 0.07 с       | 0.08 с       | 6 / 1 / 0 з 10                     |
| es                  | 41 с  | 0            | 0.13 с       | 3 / 1 / 0 з 10                     |
| fr                  | 35 с  | 0            | 0.16 с       | 5 / 2 / 0 з 10                     |
| uk → en             | 81 с  | 0            | 0.20 с       | 3 / 3 / 0 з 12                     |

- **Кроки повного прогону:** розділення ≈ 36 с (розпізнавання паралельно), вирівнювання й стать
  20 с, переклад з підгонкою 31 с, озвучка й зведення 10 с. Кожна задача — з першої спроби.
- **Вартість:** повний дубляж хвилини — $0.018 (розпізнавання $0.0107, переклад і підгонка
  $0.0071); наступна мова чи виправлення мовця з `reuseOf` — ≈ $0.006, розпізнавання й
  `audio-separate` не викликаються (видно в `dub_provider_duration_seconds`). Шість дубляжів —
  $0.06. Оцінка вище ($0.012) була з `minimal`; `low` з підгонкою дорожчий.
- **Тома записано в жінки (0.36).** По шматках: спокійна репліка 0.988, дві з криком 0.001 і
  0.002, «…in space» 0.999, репліка робота, яку діаризація віддала Тому, 0.998. Три найдовші —
  спокійний шматок і два крикливі, звідси 0.36; усі п'ять дали б 0.507. Діаризація конвеєра ріже
  репліки інакше, ніж у спайку, тож «три шматки — те саме, що все мовлення» тут не втрималось.
  Помилка однобічна: крик або високий голос робить чоловіка «жінкою» (хлопець у Sprite Fright —
  0.997 і 0.001), жіночі голоси на кожній репліці — 0.001. Правило не міняємо: виправлення
  в «Мовцях» дає чоловічий голос і рід («крутим», «наляканий», «asustado», «effrayé») за ≈ $0.006.
  Варіант на потім — усі шматки й «чоловік, якщо чоловіче хоча б третина мовлення».
- **Пропущена репліка не позначена.** «You're a jerk, Thom.» (≈ 7.5 с) не розпізнана, як і в
  спайку, але й серед нерозпізнаних фрагментів її немає (лише 29.3–30.1 с). Причину не шукали.
- **uk → en:** «Селія» → «Це ліана», а синтетичні `M1` і `M2` діаризація злила в одного мовця —
  помилки розпізнавання синтетичного голосу, як у розділі «Розпізнавання української».
