# Спайк 02. Переклад відео: розпізнавання, переклад, озвучка

- Дата: 2026-10-17
- Код: [`spikes/02-video-dub`](../../spikes/02-video-dub) (одноразовий, не частина workspace)
- Мета: виміряти час, вартість і зсув фраз до ADR-016, а не вибирати провайдерів за документацією.

## Обраний стек і чому

- Розпізнавання — `gpt-4o-transcribe-diarize` (`diarized_json`: сегменти з `start`, `end`,
  `speaker`); фолбек — `gpt-4o-transcribe` на фрагментах, нарізаних за паузами (`silencedetect`),
  бо таймкодів ця модель не повертає.
- Переклад — LLM OpenAI зі строгою JSON-схемою; вона ж визначає мову оригіналу, бо діаризаційна
  модель мову не повертає.
- Озвучка — Supertonic 3: локально (ONNX, відкриті ваги) за замовчуванням, Supertone API —
  другий адаптер. Окремий пресет-голос на кожного мовця.

Що відомо з документації на 17 жовтня 2026:

- OpenAI вимикає `whisper-1`, `gpt-4o-transcribe` і `gpt-4o-transcribe-diarize`
  26 лютого 2027. Рекомендований `gpt-transcribe` таймкодів не дає, тож інтерфейс
  `SpeechToText` потрібен уже для першої заміни.
- OpenAI вимикає `tts-1`, `tts-1-hd` і `gpt-4o-mini-tts` 6 січня 2027; заміна
  `gpt-realtime-2.1-mini` працює лише через Realtime API. Озвучка на OpenAI не розглядалась.
- Репозиторій Supertonic заархівований (вересень 2026). Ваги на Hugging Face
  (`Supertone/supertonic-3`, OpenRAIL-M: атрибуція й заборона імітувати чужий голос без
  згоди), код прикладів — MIT. Оновлень моделі не буде; це ризик, а не блокер, бо ваги в нас.

## Як повторити

```bash
cd spikes/02-video-dub
base=https://huggingface.co/Supertone/supertonic-3/resolve/main
mkdir -p assets/onnx assets/voice_styles
for f in duration_predictor.onnx text_encoder.onnx vector_estimator.onnx vocoder.onnx \
  tts.json unicode_indexer.json; do curl -sL -o assets/onnx/$f $base/onnx/$f; done
for v in M1 M2 F1 F2; do curl -sL -o assets/voice_styles/$v.json $base/voice_styles/$v.json; done

docker run --rm --cpus=2 --memory=2g -e THREADS=2 -v "$PWD":/spike -w /spike \
  node:22-bookworm-slim sh -c 'npm install && node tts-bench.mjs'
```

`vendor/supertonic-helper.js` — Node-приклад з архіву Supertonic; змінено лише те, що
`loadTextToSpeech` приймає параметри сесії ONNX (кількість потоків).

## Supertonic 3 локально: що спостерігав

Docker на Apple Silicon (arm64), `--cpus=2 --memory=2g`, `intraOpNumThreads=2`, 8 кроків
дифузії, голоси `M1` і `F1`, шість німецьких фраз від 15 до 157 символів, швидкість 1.0 і 1.3.

| Що                                 | Значення                                     |
| ---------------------------------- | -------------------------------------------- |
| Ваги                               | 407 МБ (з них `vector_estimator.onnx` — 257) |
| Завантаження моделі                | 7.4 с, +432 МіБ RSS                          |
| Пікова пам'ять процесу             | 594 МіБ                                      |
| Швидкість синтезу                  | 0.19–0.37 від тривалості аудіо (RTF)         |
| Час на хвилину мовлення            | 13.5 с (2 CPU, тобто ≈ 27 CPU-секунд)        |
| Темп німецької, швидкість 1.0      | 14.2–14.4 симв./с для звичайних речень       |
| Темп фрази з датою, часом і цінами | 7.7 симв./с                                  |
| Передбачувач тривалості            | 1–5 мс на фразу, похибка до 0.07 с           |
| Частота дискретизації              | 44.1 кГц, моно                               |

Висновки:

- **Тривалість відома до синтезу.** Модель спершу окремою маленькою мережею передбачає
  тривалість, а `speed` її просто ділить; передбачення збігається з фактичною довжиною до
  0.07 с. Тому підгонка не потребує спроб: після перекладу передбачити тривалість усіх фраз за
  мілісекунди, вибрати швидкість під слот (до 1.4), а фрази, яким і 1.4 не досить, одразу
  віддати на коротший переклад — ще до першого синтезу. `atempo` для цього адаптера не потрібен.
- **Бюджет символів — лише перше наближення.** Числа, дати й валюта розгортаються в слова: та
  сама довжина рядка звучить удвічі довше (7.7 проти 14.3 симв./с). Остаточну перевірку робить
  передбачувач, а не лічильник символів; для бюджету в запиті на переклад — 14 симв./с.
- **Ресурси пода.** 2 CPU озвучують хвилину мовлення за ~14 с, а хвилинне відео має менше
  мовлення, ніж хвилину. Під'їдає пам'ять: ~600 МіБ на процес, модель вантажиться 7 с —
  завантажувати один раз при старті пода, а не на задачу. Запит пода `video-dub` — від 1 ГіБ.
- **Alpine не підходить.** `onnxruntime-node` постачає бінарники лише під glibc; в образі
  воркера (`node:22-alpine`) він не завантажується (`ld-linux-aarch64.so.1` відсутній). Для
  `video-dub` потрібен образ на Debian (`bookworm-slim`) — окремий Dockerfile або окрема стадія.
- **Недетермінованість.** Шум дифузії береться з `Math.random`, тож повтор синтезу дає трохи
  інший звук тієї ж тривалості. Для чекпоінтів це не важливо — готовий кліп не синтезується
  вдруге.

Якість на слух (вимова чисел, природність на швидкості 1.3) — у `out/tts/*.wav`; оцінка — після
прослуховування.

## Увесь конвеєр на фейкових провайдерах

Тестове відео — хвилина «Tears of Steel» (0:15–1:15; © Blender Foundation, mango.blender.org,
CC BY 3.0; саундтрек — CC BY-ND 3.0, тож результати дубляжу не публікуються й не комітяться):
суперечка двох героїв під музику, голос робота, ще одна репліка — 11 фраз, 4 мовці.

- Розпізнавання — фейк з англійських субтитрів фільму, мовці розмічені вручну. Таймінг субтитрів
  трохи ширший за мовлення, для таймлайну цього досить.
- Переклад — фейк з німецьких субтитрів фільму: людський переклад, але для читання, а не для
  дубляжу; скорочувати на запит він не вміє.
- Озвучка, підгонка, зведення, монтаж і VTT — справжні.

```bash
cd spikes/02-video-dub
docker build -t pdp-spike-dub .        # Debian + ffmpeg 5.1 — форма образу для video-dub
docker run --rm -v "$PWD":/w -w /w --entrypoint sh pdp/video-worker:dev -c \
  'ffmpeg -ss 15 -t 60 -i https://download.blender.org/demo/movies/ToS/tears_of_steel_720p.mov \
   -c:v libx264 -preset veryfast -crf 23 -c:a aac -b:a 160k input/tos-1min.mp4'
curl -s -o input/TOS-en.srt https://download.blender.org/demo/movies/ToS/subtitles/TOS-en.srt
curl -s -o input/TOS-de.srt https://download.blender.org/demo/movies/ToS/subtitles/TOS-de.srt
docker run --rm --cpus=2 --memory=2g -e VOICES=F1,M1,M2,F2 -v "$PWD":/spike pdp-spike-dub \
  node dub.mjs
```

Перемикачі: `STT=fake|diarize|chunked`, `TRANSLATOR=fake|openai`, `MODEL`, `VOICES`, `THREADS`.
Платні кроки кешуються в `out/…/*.json`, як чекпоінти процесора; `FRESH=1` їх ігнорує.

Що спостерігав (2 CPU):

| Крок                        | Час                       |
| --------------------------- | ------------------------- |
| Завантаження моделі         | 5–7 с (раз на под)        |
| Витяг аудіо (FLAC 16 кГц)   | 0.15 с, 2.1 МБ на хвилину |
| Передбачення тривалості, 11 | 52 мс                     |
| Озвучка, 528 символів       | 8 с                       |
| Зведення з приглушенням     | 1 с                       |
| Монтаж без перекодування    | 0.2 с                     |

- **Своя частина конвеєра — близько 10 с на хвилину відео** на 2 CPU. Решта часу — мережеві
  виклики розпізнавання й перекладу; їх доміряю з ключем.
- **Скорочення перекладу — не крайній випадок, а основний шлях.** Субтитровий переклад довший за
  мовлення: 5 з 11 фраз не влазять у свій слот навіть на швидкості 1.4, 9 з 11 прискорені. Без
  скорочення зсув накопичується у швидкому діалозі, де фрази йдуть впритул: до 5 с, 7 фраз
  починаються пізніше ніж на 0.5 с. Критерій етапу (≈ 0.5 с) тримається лише на LLM, що пише
  коротко з самого початку й скорочує на запит.
- **Передбачувач у конвеєрі** помиляється на 0.00–0.06 с проти фактичної довжини кліпу.
- **Голос за чергою мовців не знає статі:** Селія отримала чоловічий `M1`, Том — жіночий `F1`.
  Варіанти: оцінити висоту голосу мовця з оригінального аудіо (без API), дати вибрати голоси в
  UI, або пресети чоловічий/жіночий за висотою плюс вибір у UI. Рішення — в ADR-016.
- **Вихідний MP4** — відео без перекодування, `deu` за замовчуванням, `eng` другою, VTT за
  фактичними позиціями фраз. ffmpeg 5.1 з Debian має все потрібне (`sidechaincompress`,
  `amix normalize=0`).
- **Хвилина — ліміт дубляжу** (рішення 17.10): усе аудіо йде в розпізнавання одним запитом, без
  нарізки на шматки.

## Ще не виміряно

Адаптери OpenAI (`providers/openai.mjs`) написані, але ще не запускались — потрібен ключ:

- `STT=diarize`: довжина сегментів діаризації проти субтитрів, чи правильно розділені мовці, чи
  треба ділити довгі сегменти;
- `STT=chunked`: чи знаходить `silencedetect` паузи, коли під голосом музика;
- `TRANSLATOR=openai`: частка фраз, яким потрібне скорочення, і зсув початку фраз після нього —
  головна перевірка критерію 0.5 с;
- повний час і вартість хвилини; приглушення музики на слух.

Supertone API — якщо буде ключ.
