# Етап 5c.3. Каркас UI і дизайн-система — дизайн

- Дата: 2026-10-14
- Гілка: `feature/stage-5c.3-ui-shell` (від `feature/stage-5c.2-assets`)
- План: [stages-5c-5d.md, кроки 5c.3](../../plan/stages-5c-5d.md)

## Мета і межі

Перетворити односторінковий `WorkspacePage` на застосунок із маршрутами, спільним каркасом і
дизайн-системою, на якій 5c.4 збудує екрани входу, медіатеки й налаштувань, а 5d — переклад відео.

**Входить:** IA і user flows, вайрфрейми в репозиторії, токени, примітиви з плану, react-router з
layout routes і охороною, перенесення наявних видів, стани завантаження / помилки / порожнечі,
`aria-live` для статусів, документація.

**Не входить (5c.4 і далі):** форми входу за email і паролем та реєстрації, екрани медіатеки,
сторінки файлу і налаштувань (у 5c.3 — заглушки), SSG (5c.5), маршрути перекладу (5d).

## Ухвалені рішення

| Питання              | Рішення                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Роутер               | react-router v7 у data mode: `createBrowserRouter`, route objects, `lazy`. Для SSG у 5c.5 є `createStaticHandler` і `StaticRouterProvider`                             |
| Примітиви            | Власні, поверх нативних елементів (`<dialog>`, `<select>`, `<progress>`, checkbox / radio); Tabs і Toast — за WAI-ARIA APG; без нових залежностей, крім `react-router` |
| «Користувач увійшов» | Успішний `GET /v1/me` (cookie-сесія або `X-API-Key`). `/login` у 5c.3 показує наявну форму API-ключа                                                                   |
| Вайрфрейми           | SVG у репозиторії, user flows — Mermaid; без Figma                                                                                                                     |
| Назви токенів        | Лишаються з метафори «світлового столу» (`--table`, `--mount`, `--ink`, …), прогалини заповнюються                                                                     |

Відкинуті варіанти: declarative mode (`<BrowserRouter>` + `React.lazy`) — у 5c.5 lazy-маршрути й
пререндер довелося б зшивати вручну; framework mode з вбудованим `prerender` — підміняє збірку і
забирає навчальну мету 5c.5 (`renderToString`, `hydrateRoot`, hydration mismatch); React Aria і
Radix — зайві залежності для десятка примітивів, коли нативні елементи дають фокус, Esc і inert-фон.

## 1. Інформаційна архітектура і маршрути

### Публічний каркас — `PublicLayout`

Логотип, перемикач мови, посилання «Увійти» і «Зареєструватися».

- `/` — що робить сервіс; у 5c.5 ця сторінка стане статичною.
- `/login` — у 5c.3 форма API-ключа (`ApiKeyForm`). Після успіху — перехід на `?next=` або
  `/library`. Якщо `GET /v1/me` уже успішний, `/login` одразу переводить на `next`.
- `/register` — заглушка з поясненням і посиланням на вхід; форма — у 5c.4.

`next` приймається лише як внутрішній шлях: починається з `/`, не з `//` і не містить `\`.
Інакше — `/library`. Це захист від open redirect.

### Каркас застосунку — `AppLayout` під `RequireAuth`

- Шапка: бренд, навігація «Медіатека · Задачі · Вебхуки» (`NavLink` з `aria-current="page"`),
  кнопка «Завантажити», меню користувача.
- Меню користувача — disclosure (кнопка з `aria-expanded` і список), закривається Esc, кліком
  поза меню і після вибору. Вміст: ім'я або email, «Налаштування», мова, «Документація API»
  (`/docs`, нова вкладка), «Вийти».
- На ширині до 40rem навігація переноситься рядком під шапку, меню згортається в кнопку з
  ініціалом.

| Маршрут                   | У 5c.3                                           | Далі                                                          |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------------------- |
| `/library`                | заглушка: заголовок і `EmptyState`               | 5c.4 — сітка файлів, фільтр, курсор                           |
| `/library/:id`            | заглушка                                         | 5c.4 — оригінал, результати, видалення; 5d — дія «Перекласти» |
| `/library/:id/dub/:jobId` | немає, лише в IA                                 | 5d — перегляд перекладу                                       |
| `/jobs`                   | `JobsView` + `ContactSheet`, фільтр у `?status=` | —                                                             |
| `/webhooks`               | `WebhooksView`                                   | —                                                             |
| `/settings`               | заглушка                                         | 5c.4 — API-ключі, профіль                                     |
| `*`                       | «Не знайдено» з посиланням на медіатеку          | —                                                             |

`/` для залогіненого користувача лишається публічною сторінкою з кнопкою «Відкрити медіатеку».

### Охорона — `RequireAuth`

`useGetMeQuery()`:

- завантаження → скелет каркаса;
- `401` → `<Navigate to="/login?next=<pathname+search>" replace />`;
- інша помилка → `ErrorState` з «Спробувати ще раз» (для `429` / `503` — відлік `Retry-After`);
- успіх → `<Outlet />`; меню читає той самий закешований `me`.

`401` на будь-якому запиті: якщо збережено API-ключ — `apiKeyRejected` (як зараз), і в будь-якому
разі інвалідується тег `Me`, тож охорона переводить на вхід.

«Вийти»: `authMethod === 'api-key'` — `apiKeyCleared`; `'session'` — `POST /v1/auth/logout`. Далі
скидається кеш RTK Query і перехід на `/login`.

## 2. Токени і примітиви

### Токени — `shared/ui/tokens.css`

Імпортується з `app/global.css`. Наявні назви лишаються. Додається:

- статусні тони: `--tone-neutral`, `--tone-progress`, `--tone-success`, `--tone-warning`,
  `--tone-danger` і фонові `--tone-*-wash`;
- контраст WCAG 2.2 AA: кожна пара «текст / фон», що використовується, має ≥ 4.5:1, для великого
  тексту й меж контролів ≥ 3:1. `--amber` (`#b06a00`) на `--mount` дає ≈ 4.1:1, тому для тексту
  з'являється темніший варіант. Пари фіксує unit-тест, що рахує контраст за формулою WCAG;
- `--text-lg`, ваги (`--weight-regular`, `--weight-medium`, `--weight-bold`), `--radius-pill`,
  `--shadow-overlay`, шари `--z-header`, `--z-overlay`, `--z-toast`, тривалості
  `--motion-fast`, `--motion-slow`; під `prefers-reduced-motion: reduce` тривалості нульові.

### Примітиви — `shared/ui/<name>/`

Кожен — тека з `Component.tsx`, `Component.module.css`, `Component.test.tsx`; імпорт за шляхом,
без barrel-файлу. Обгортки приймають пропси нативного елемента (`ComponentProps<'button'>` тощо)
і передають їх далі. Без мережі й доменних знань.

| Примітив                          | Основа                                   | Поведінка                                                                                                                                                                                       |
| --------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Button`                          | `<button>`                               | `variant`: `primary` / `secondary` / `quiet` / `danger`; `size`: `md` / `sm`; `isBusy` → `aria-busy`, блок кліку; `type="button"` за замовчуванням; `buttonClass({ variant, size })` для `Link` |
| `Field`, `Input`                  | `<label>`, `<input>`                     | `Field` приймає `label`, `hint`, `error` і render-функцію з `{ id, 'aria-describedby', 'aria-invalid' }`                                                                                        |
| `Select`                          | `<select>`                               | лише стилі                                                                                                                                                                                      |
| `Checkbox`, `Radio`, `RadioGroup` | input, `fieldset` / `legend`             | `accent-color` з токена; мітка — частина компонента                                                                                                                                             |
| `Card`                            | `<div>`                                  | «слайд»: `--mount`, `--shadow-mount`, `--radius-mount`                                                                                                                                          |
| `Badge`                           | `<span>`                                 | `tone` + текст; колір не єдиний носій сенсу                                                                                                                                                     |
| `Progress`                        | `<progress>`                             | обов'язковий підпис; без `value` — невизначений                                                                                                                                                 |
| `Dialog`                          | `<dialog>`, `showModal()`                | `open` / `onClose`; Esc (подія `cancel`) і клік по фону закривають; заголовок через `aria-labelledby`; фокус повертається на елемент, що відкрив                                                |
| `ToastProvider`, `useToast`       | регіони `role="status"` / `role="alert"` | `toast({ tone, message, action? })`; зникає через 5 с, пауза під курсором або фокусом; кнопка «Закрити»; до 3 одночасно                                                                         |
| `Tabs`                            | APG tabs                                 | автоматична активація, roving tabindex, ←/→, Home, End                                                                                                                                          |
| `Skeleton`                        | `<div aria-hidden>`                      | розміри пропсами; контейнер ставить `aria-busy`; без мерехтіння при reduced motion                                                                                                              |
| `EmptyState`                      | —                                        | заголовок, текст, слот дії                                                                                                                                                                      |
| `ErrorState`                      | —                                        | `role="alert"`, заголовок, текст, `onRetry`                                                                                                                                                     |

Текст для людини з `AppError` готує `describeError(error, t)` у `shared/lib`; `ErrorState`
отримує готові рядки. `Toast` — єдиний примітив із контекстом; провайдер ставиться в `Providers`.

У `test/setup.ts` — мінімальний поліфіл `HTMLDialogElement.prototype.showModal` / `close` для
jsdom (ставить і знімає `open`, шле `close`).

## 3. Каркас, перенесення і стани

### Структура

```
app/
  router.tsx              # дерево маршрутів, lazy-сторінки
  layouts/                # PublicLayout, AppLayout, RequireAuth, UserMenu, LanguageSwitch
  Providers.tsx           # + RouterProvider, ToastProvider
features/
  session/                # getMe, logout, тег Me
  upload/ui/UploadDialog  # Dialog + наявна UploadPanel
pages/
  landing/ login/ register/ library/ asset/ jobs/ webhooks/ settings/ not-found/
shared/ui/                # tokens.css і примітиви
```

- `WorkspacePage`, `use-view-param` видаляються. `ContactSheet`, `SlideMount`, `Countdown`,
  `sheet-items`, `describe-item`, `timecode` переїжджають у `pages/jobs/`; `WebhooksView` — у
  `pages/webhooks/`. `use-status-param` замінює `useSearchParams` з react-router.
- Сторінки експортуються іменовано: `lazy: () => import('../pages/jobs/JobsPage').then((m) => ({ Component: m.JobsPage }))`.
- Наявні стилі кнопок (`button.module.css`) переходять на `Button`; CSS-модулі видів —
  на токени без змін вигляду.

### Діалог завантаження

Кнопка «Завантажити» в шапці відкриває `UploadDialog` з `UploadPanel` (пресети і режим відео —
вибір дії; у 5c.4 додадуться дії медіатеки). Після вибору файлів діалог закривається, з'являється
тост «Завантажуємо N файлів» з дією «Відкрити задачі» (на `/jobs` без дії). Помилка завантаження —
тост з `role="alert"`. Стан завантажень лишається в слайсі `uploads`, тож перехід між сторінками
його не губить; слайди, як і зараз, з'являються в `ContactSheet`. На `/jobs` порожній стан має дію
«Завантажити перший файл», що відкриває той самий діалог.

### Стани асинхронних екранів

- Завантаження — `Skeleton` у формі вмісту (слайди на `/jobs`, рядки на `/webhooks`).
- Помилка — `ErrorState`; для `429` / `503` — відлік `Retry-After` (наявний `Countdown`).
- Порожньо — `EmptyState` з дією.

`SheetMessage` і `message`-блоки `WebhooksView` замінюються цими примітивами.

### Доступність

- Статуси задач: один прихований регіон `aria-live="polite"` на `/jobs`, що оголошує лише переходи
  в кінцевий стан («photo.png — готово», «clip.mp4 — помилка»). Перше завантаження списку не
  оголошується.
- Після переходу між маршрутами фокус іде на `h1` сторінки (`tabIndex={-1}`), `document.title` —
  «<сторінка> — PDP Media Pipeline». Перший рендер фокус не чіпає.
- Мінімальна ціль натискання 24×24 px; видимий фокус — наявний `:focus-visible`.

## Тестування

- Примітиви — поведінка через DOM: клавіатура `Tabs`, Esc / фон / повернення фокуса `Dialog`,
  автозникнення й пауза `Toast` (fake timers), зв'язки `Field`, `isBusy` у `Button`.
- Токени — тест контрасту пар.
- Застосунок — `renderApp({ route })` поверх `createMemoryRouter` з тим самим деревом маршрутів;
  `App.test.tsx` ділиться за сторінками. Сценарії:
  - без сесії `/webhooks` → `/login?next=%2Fwebhooks`, після входу ключем — назад на `/webhooks`;
  - `next=//evil.example` → `/library`;
  - невідомий шлях → «Не знайдено»;
  - діалог завантаження з `/webhooks`, тост веде на `/jobs`;
  - «Вийти» з ключем і з сесією (`POST /v1/auth/logout`);
  - перехід задачі в `succeeded` оголошується в live-регіоні;
  - наявні сценарії задач і вебхуків переносяться без втрат.
- Перевірки: `pnpm --filter @pdp/web test`, typecheck, lint, prettier.

## Критерій готовності

Користувач з ключем відкриває `/jobs` і `/webhooks` з навігацією, завантажує файл із будь-якої
сторінки, бачить скелети, помилки й порожні стани; без входу потрапляє на `/login` і після входу
повертається туди, звідки прийшов; усі наявні тести проходять у новій структурі; документи IA,
flows, вайрфрейми й дизайн-система лежать у `docs/design/`.
