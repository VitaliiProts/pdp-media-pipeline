# Етап 5c.4. Екрани входу, медіатеки й налаштувань — дизайн

- Дата: 2026-10-15
- Гілка: `feature/stage-5c.4-screens` (від `main` після злиття 5c.2 і 5c.3)
- План: [stages-5c-5d.md, кроки 5c.4](../../plan/stages-5c-5d.md)
- Каркас і примітиви: [дизайн 5c.3](2026-10-14-stage-5c3-ui-shell-design.md),
  [IA](../../design/information-architecture.md), [вайрфрейми](../../design/wireframes/)

## Мета і межі

Наповнити каркас 5c.3 справжніми екранами: вхід і реєстрація за email і паролем, медіатека з
фільтрами й нескінченною прокруткою, сторінка файлу з версіями й видаленням, налаштування з
API-ключами. Браузер працює лише з cookie-сесією; API-ключі лишаються для скриптів.

**Входить:** фіча `auth` замість `api-key` і `session`; медіатека і сторінка файлу; зміни діалогу
завантаження (перехід у медіатеку, квота); налаштування; дописи бекенду, без яких екрани не
виконують план: фільтр за статусом і пошук у `GET /v1/assets`, `downloadUrl`, `seed-user` з
паролем.

**Не входить:** SSG і опис сервісу на `/` (5c.5), переклад відео (5d), відновлення пароля й
підтвердження email (ADR-013), редагування профілю, індекс pg_trgm для пошуку.

## Ухвалені рішення

| Питання                   | Рішення                                                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Обсяг                     | Один PR на весь 5c.4                                                                                                          |
| Статус і пошук            | Бекенд: `GET /v1/assets?status=&q=`; статус — з останньої задачі файлу, пошук — `ILIKE` з екрануванням, без pg_trgm           |
| Вхід за API-ключем у UI   | Прибирається повністю; ключ не зберігається в браузері. `seed-user` приймає `--email` і `--password` для дев-акаунта          |
| Після старту завантаження | Діалог закривається і веде на `/library`; файли в роботі — першими в сітці                                                    |
| Дані медіатеки            | RTK Query `infiniteQuery` (RTK 2.13): кеш на набір фільтрів, курсор з `nextCursor`, опитування лише поки є що оновлювати      |
| Завантаження файлів       | `downloadUrl` — presigned GET з `response-content-disposition: attachment`, бо атрибут `download` не працює для іншого origin |

Відкинуті варіанти: `serializeQueryArgs` + `merge` — після інвалідації чи опитування лишається
лише перша сторінка; посторінкова навігація — план вимагає нескінченну прокрутку; фільтрація на
клієнті — з курсорною пагінацією бачила б лише завантажені сторінки; ключ у пам'яті як другий
спосіб входу — два шляхи автентифікації в UI без користі для користувача.

## 1. Бекенд

### Фільтри медіатеки — `GET /v1/assets`

`ListAssetsQuery` у `@pdp/contracts` отримує два необов'язкові параметри поруч із `kind`,
`limit` і `cursor`:

| Параметр | Значення                          | Умова в Metadata                                                                 |
| -------- | --------------------------------- | -------------------------------------------------------------------------------- |
| `status` | `processing`                      | остання задача файлу в `queued`, `scheduled` або `running`                       |
|          | `ready`                           | остання задача `succeeded`                                                       |
|          | `failed`                          | остання задача `failed` або `dead`                                               |
| `q`      | рядок 1–100 символів після `trim` | `name ILIKE '%' \|\| q \|\| '%' ESCAPE '\'`, де `%`, `_` і `\` у `q` екрануються |

«Остання задача» — та сама, що в `latestJob`: корельований підзапит
`(SELECT status FROM jobs WHERE asset_id = assets.id ORDER BY created_at DESC, id DESC LIMIT 1)`,
що читає `jobs_asset_created_idx`. Курсор і порядок `(createdAt, id)` не змінюються: фільтри лише
звужують вибірку. Gateway: DTO з `class-validator`, Swagger, прокидання в Metadata-клієнт.

### Завантаження — `downloadUrl`

`StorageService.presignGet(key, ttl, { downloadName? })` додає `ResponseContentDisposition:
attachment; filename*=UTF-8''<percent-encoded name>`. У `GET /v1/assets/:id` біля кожного `url`
з'являється `downloadUrl`: у оригіналу (`originalDownloadUrl`), у кожного результату
`image.resize`, кожного рендишну `video.transcode`, прев'ю й кожного кадру `video.frames`. Ім'я
для завантаження: оригінал — `asset.name` (або останній сегмент ключа), результат —
`<назва без розширення>-<суфікс>.<розширення результату>`, де суфікс — пресет (`thumb`), рендишн
(`480p`), `preview` або `frame-0001`. Підпис рахується
локально, мережевих запитів не додається. `GET /v1/jobs` не змінюється.

### `seed-user`

Необов'язкові `--email` і `--password`: якщо задані, користувач створюється з email і хешем
argon2id тими самими функціями, що й реєстрація, і може увійти в UI. Без них — як зараз:
користувач без пароля з API-ключем.

### Тести бекенду

- Metadata, інтеграційні: `status` для кожного значення, зокрема коли старіша задача успішна, а
  остання впала; `q` з `%` і `_` у назві та в запиті; комбінація `kind` + `status` + `q` з
  курсором на дві сторінки.
- Gateway: валідація `status` і `q` (400 на невідоме значення й на 101 символ); `downloadUrl` має
  `response-content-disposition` з закодованим ім'ям; наявний тест ізоляції лишається.
- `seed-user`: користувач з `--email` / `--password` входить через `POST /v1/auth/login`.

## 2. Вхід, реєстрація, вихід

### Фіча `auth`

`features/auth` замінює `features/session` і `features/api-key`:

- `api/auth-api.ts` — RTK Query: `getMe` (тег `Me`), `login`, `register`, `logout`;
- `ui/LoginForm.tsx`, `ui/RegisterForm.tsx`;
- `model/signed-out.ts` — `createAction('auth/signedOut')`: стану в `auth` немає, сесію знає лише `getMe`;
- `model/validate.ts` — клієнтські правила; межі (`PASSWORD_MIN_LENGTH` 8, `PASSWORD_MAX_LENGTH`
  128, `EMAIL_MAX_LENGTH` 254) дублюються з `@pdp/contracts` з посиланням у коментарі: web не
  залежить від `zod`, а сервер лишається джерелом правди.

`shared/api/http.ts`: без `getApiKey` і заголовка `X-API-Key`. `onUnauthorized(url)` викликається
на `401` будь-якого запиту, крім `/v1/auth/*` (там `401` — неправильний пароль, а не кінець
сесії). `AppError` варіанта `http` отримує `code: string | null` з тіла відповіді
(`EMAIL_TAKEN`, `ASSET_BUSY`, `STORAGE_QUOTA_EXCEEDED`, …).

Стор: слухач на `signedOut` перериває `sessionSignal`, викликає `clearUploads()` і
`baseApi.util.resetApiState()`; слухач на успішний `login` / `register` скидає кеш API
попереднього користувача; підписані запити, зокрема `getMe`, перезапитуються (так само працював
`apiKeySaved` у 5c.3). `onUnauthorized` інвалідує `Me`, тож `RequireAuth`
веде на вхід зі збереженням адреси. Старий `pdp.apiKey` один раз видаляється з `localStorage`
в ефекті `AppRoot` (не в ініціалізації — під SSG у 5c.5).

Фронтенд і `/v1` на одному origin (nginx у compose і k3d, proxy у Vite), тож cookie
`HttpOnly; SameSite=Lax` іде без `withCredentials`, а перевірка `Origin` на Gateway проходить.

### Сторінки `/login` і `/register`

- Користувач, що вже увійшов, одразу йде на `safeReturnTo(next)` або `/library`.
- Після успіху `GET /v1/me` перезапитується, і сторінка робить той самий перехід.
- `/login`: email, пароль, «Увійти»; посилання «Немає акаунта? Зареєструватися» (зберігає `next`).
- `/register`: ім'я (необов'язкове), email, пароль з підказкою «щонайменше 8 символів»,
  «Зареєструватися»; посилання на вхід.
- `autocomplete`: `email`, `current-password` / `new-password`, `name`.
- Помилка перевірки сесії, що не `401`, — `ErrorState` над формою (як після рев'ю 5c.3).

### Помилки форм

| Ситуація                      | Що бачить людина                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| Порожнє поле, формат, довжина | Перевірка на submit; помилка в `Field` під полем, фокус на першому хибному полі             |
| `401` на вході                | «Невірний email або пароль» у `role="alert"` над кнопкою; пароль очищується, фокус на ньому |
| `409 EMAIL_TAKEN`             | Помилка на полі email з посиланням «Увійти»                                                 |
| `400` від сервера             | Повідомлення сервера в `role="alert"` (клієнтські правила мають ловити це раніше)           |
| `429` з `Retry-After`         | «Забагато спроб. Спробуйте через N с», відлік; кнопка недоступна, поки він не закінчиться   |
| Мережа, `5xx`                 | «Не вдалося зв'язатися з сервером. Спробуйте ще раз»                                        |

### Вихід

Меню користувача: `POST /v1/auth/logout`, потім `signedOut` і перехід на `/login`. Помилка
виходу — тост, як зараз. Сплила сесія посеред роботи: перший `401` інвалідує `Me`, і охорона веде
на вхід; завантаження, що ще йдуть, отримують `401` і показуються як «не вдалося».

## 3. Медіатека — `/library`

### Структура

```
features/assets/
  api/assets-api.ts        listAssets (infiniteQuery), getAsset, deleteAsset; тег Asset
  model/types.ts           Asset, AssetSummary, AssetDetails, AssetStatus
  model/use-live-assets.ts інтервал опитування з кешу
  ui/AssetTile.tsx         плитка серверного файлу
  ui/DeleteAssetButton.tsx кнопка + Dialog підтвердження
pages/library/
  LibraryPage.tsx
  ui/LibraryFilters.tsx, ui/AssetGrid.tsx, ui/UploadTile.tsx, ui/LoadMore.tsx
  lib/use-library-params.ts фільтри ↔ URL
```

### Фільтри в URL

`?kind=image|video&status=processing|ready|failed&q=…`. Невідомі значення ігноруються, як у
`use-status-param`.

- Тип — перемикач «Усі · Фото · Відео» (`ChoiceGroup` з радіокнопками у вигляді сегментів).
- Статус — `Select`: «Будь-який статус / Обробляється / Готово / Помилка».
- Пошук — `Input type="search"` з підписом «Пошук за назвою»; `q` пишеться в URL через 300 мс
  після останньої клавіші з `replace: true`. Зміни типу й статусу додають запис в історію.

### Сітка й плитки

CSS grid `repeat(auto-fill, minmax(11rem, 1fr))`: 2 колонки на 375 px, 4–5 на 1280 px.
Сітка — `<ul>`, плитка — `<li>` з `Card` і посиланням на `/library/:id`, що передає поточні
фільтри в `location.state`.

- Прев'ю: `preview.url` з `width` і `height`, `loading="lazy"`, `alt=""` (назва — текст
  посилання). Відео: кадр-прев'ю, позначка «Відео» і тривалість `m:ss`.
- Без прев'ю (ще обробляється або впало): заглушка з іконкою типу.
- Під прев'ю: назва (обрізана, повна в `title`), `Badge` статусу останньої задачі, вага.

### Файли в роботі

Лише у вигляді без фільтрів: перед серверними плитками — локальні з `selectUploads`
(`UploadTile`): прев'ю з `objectURL` для картинок, `Progress`, «чекаємо N с», «не вдалося» з
причиною й кнопкою «Прибрати». Плитка зникає, коли серед завантажених сторінок є asset з
`latestJob.id === upload.jobId`; запис у слайсі лишається для `/jobs`. Thunk завантаження після
`POST /v1/jobs` інвалідує `Job` і `Asset`.

### Живі статуси

`useLiveAssets`: інтервал 3 с, поки на завантажених сторінках є файл зі статусом `queued`,
`scheduled` або `running`, або є відправлене завантаження, якого ще немає в списку; інакше
опитування немає. `skipPollingIfUnfocused`; після `429` / `503` — `Retry-After`. 3 с замість
1 с на `/jobs`: опитування `infiniteQuery` перезапитує всі завантажені сторінки.

### Нескінченна прокрутка

Sentinel під сіткою з `IntersectionObserver` (`rootMargin: 600px`) викликає `fetchNextPage`,
коли `hasNextPage && !isFetchingNextPage`. Поруч завжди видима кнопка «Показати ще» — для
клавіатури, скрінрідерів і браузерів без `IntersectionObserver`. Регіон
`aria-live="polite"` оголошує «Додано ще N файлів». Фокус не переміщується.

### Стани

| Стан                       | Вигляд                                                                    |
| -------------------------- | ------------------------------------------------------------------------- |
| Перше завантаження         | Скелет сітки (8 плиток) з `role="status"` і `aria-busy`                   |
| Помилка першої сторінки    | `ErrorState` з повтором і текстом за `retryAfterOf`                       |
| Порожньо без фільтрів      | `EmptyState` «Тут з'являться ваші файли» з кнопкою «Завантажити» (діалог) |
| Порожньо з фільтрами       | `EmptyState` «Нічого не знайдено» з посиланням «Скинути фільтри»          |
| Помилка наступної сторінки | Повідомлення з повтором під сіткою; завантажені плитки лишаються          |

## 4. Сторінка файлу — `/library/:id`

### Шапка

- Хлібні крихти «Медіатека / назва»; посилання повертає фільтри з `location.state`, якщо вони є.
- `PageHeading` з назвою файлу.
- Факти: розміри, тривалість (відео), вага, тип, дата завантаження (`Intl.DateTimeFormat` мови
  інтерфейсу).
- Дії: «Завантажити оригінал» (`originalDownloadUrl`), «Видалити» (`danger`).

### Оригінал

- Картинка — ціла, `max-height: 70vh`, з `width` / `height`.
- Відео — `<video controls preload="metadata" poster={preview}>`. Джерело — 720p, якщо готовий,
  інакше 480p; `ChoiceGroup` «720p / 480p» перемикає, якщо готові обидва. Без транскодингу
  плеєр грає оригінал; якщо браузер його не відтворює (`error` на `<video>`, напр. `.mov`), —
  прев'ю з підказкою «Браузер не відтворює цей формат. Зробіть транскодинг у 480p / 720p».

### Вкладки

`Tabs` з 5c.3 («Переклад» додасться на 5d):

- **Версії** — результати всіх успішних задач, новіші вище. Рядок: мініатюра, назва
  («Мініатюра 200 px», «Середній 800 px», «480p», «Кадр-прев'ю»), розміри, вага, формат
  (WebP, MP4, JPEG), «Завантажити» (`downloadUrl`). Кадри `video.frames` — стрічка мініатюр з
  позначкою часу, кожна — посилання на завантаження. Немає версій — текст «Версії з'являться,
  коли обробка завершиться».
- **Задачі** — до 50 задач: тип, `Badge` статусу, час створення, спроби, остання помилка,
  `TraceLink`. Є `jobsNextCursor` — підпис «Показано 50 найновіших задач».

### Видалення

`DeleteAssetButton` відкриває `Dialog`: «Видалити harbour.jpg? Оригінал і всі версії зникнуть
назавжди» з кнопками «Видалити» (`danger`, `isBusy` під час запиту) і «Скасувати».

| Відповідь        | Що відбувається                                                                          |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `204`            | Тост «Файл видалено», інвалідація `Asset`, перехід на `/library` з `replace`             |
| `404`            | Те саме: файл уже видалено                                                               |
| `409 ASSET_BUSY` | У діалозі: «Файл ще обробляється. Спробуйте, коли задача завершиться»                    |
| Інша помилка     | У діалозі: «Не вдалося видалити» і текст сервера, якщо він є; діалог лишається відкритим |

### Живі дані й стани

Опитування 3 с, поки є задача в `queued`, `scheduled` або `running`; `refetchOnFocus`, бо
presigned URL мають термін дії. Стани: скелет; `404` — `EmptyState` «Файл не знайдено» з
посиланням у медіатеку; інша помилка — `ErrorState` з повтором.

## 5. Діалог завантаження, налаштування

### Діалог завантаження

- Вибір дії лишається: пресети для картинок, «кадри» / «транскодинг» для відео; блок отримує
  заголовок «Що зробити».
- Після вибору файлів діалог закривається, а `AppLayout` веде на `/library`, якщо людина не там.
  Тост «Завантажуємо N файлів» — без дії.
- `useUploadFailureToasts` мовчить на `/library` і `/jobs`: там помилку видно на плитці.
- Нова проблема `quotaExceeded` з `413 STORAGE_QUOTA_EXCEEDED`: на плитці «Місце закінчилося:
  видаліть непотрібні файли»; поза `/library` і `/jobs` — тост-тривога.

### Налаштування — `/settings`

Розділи — `Card` з `h2`:

- **Профіль**: ім'я, email; лише читання.
- **Мова**: `LanguageSwitch`.
- **API-ключі** (`features/api-keys`):
  - Список: назва, префікс `pdp_ab12…`, створено, «востаннє використано» або «ніколи»,
    «Відкликати».
  - Форма «Новий ключ»: назва 1–100 символів, «Створити». На 10 ключах (`API_KEY_MAX_PER_USER`)
    форма недоступна з поясненням «Досягнуто ліміту в 10 ключів — відкличте непотрібний».
  - Після створення `Dialog` показує повний ключ один раз: поле лише для читання, «Копіювати»
    (`navigator.clipboard.writeText`; без нього — виділення тексту й підказка Ctrl/⌘+C),
    попередження «Більше не покажемо», приклад `curl -H "X-API-Key: <ключ>" …/v1/jobs`.
  - Відкликання — `Dialog` підтвердження, `DELETE /v1/api-keys/:id`, оновлення списку.
  - Стани списку: скелет, `ErrorState`, порожній («Ключів ще немає. Вони потрібні для скриптів
    і інтеграцій»).

Vitest + MSW за шаблонами 5c.3 (`renderApp`, MSW-обробники за замовчуванням у
`test/server.ts`). MSW тримає сесію як стан у пам'яті, який вмикають `login` і `register`.

- **Вхід:** успіх і повернення за `next`; уже ввійшов — перехід; `401`; `429` з відліком;
  мережа; фокус на першому хибному полі.
- **Реєстрація:** успіх; `409 EMAIL_TAKEN`; клієнтська валідація.
- **Вихід:** через меню; посеред завантаження (переривання й очищення, тест з 5c.3
  переписується під сесію); сплила сесія — перехід на вхід.
- **Медіатека:** фільтри потрапляють в URL і запит; невідомі значення ігноруються; пошук з
  дебаунсом; наступна сторінка через кнопку і через sentinel (мок `IntersectionObserver`);
  оголошення «Додано ще N»; локальні плитки і їх зникнення; опитування вмикається й
  вимикається; усі стани.
- **Сторінка файлу:** версії картинки й відео; перемикач 720p / 480p; видалення `204`, `404`,
  `409`; `404` сторінки.
- **Налаштування:** створення ключа з одноразовим показом і копіюванням; ліміт 10;
  відкликання; стани списку.
- **Діалог:** перехід у медіатеку після старту; `413` → `quotaExceeded`.
- **Бекенд:** див. розділ 1.

## Критерій готовності

- У compose і k3d можна зареєструватися, увійти, завантажити фото й відео, побачити їх у
  медіатеці з живими статусами, відкрити файл, переглянути версії, завантажити й видалити;
  створити й відкликати API-ключ і викликати API з ним через `curl`.
- Фільтри, пошук і прокрутка працюють з клавіатури; стан фільтрів переживає перезавантаження.
- `pnpm lint`, `format:check`, `typecheck`, `depcruise`, `test`, `test:web`, `test:int`, `build`
  зелені.
- Ключ API більше не зберігається в браузері; `features/api-key` і `features/session` видалено.

## Відхилення під час реалізації

Формат: що казала специфікація → що зроблено → чому.

### Структура

- **Плитка файлу.** `features/assets/ui/AssetTile.tsx` → `pages/library/ui/AssetTile.tsx`. Плитці
  потрібні `STATUS_LABEL_KEY` і `STATUS_TONE` з `features/jobs`, а фіча не імпортує іншу фічу.
  Окремого `AssetGrid.tsx` немає: сітка — `<ul>` у `LibraryPage`; логіка файлів у роботі —
  `pages/library/model/pending-uploads.ts`, фокус і оголошення «Показати ще» —
  `pages/library/lib/use-next-page-a11y.ts`.
- **`LanguageSwitch`.** Розділ «Мова» мав узяти перемикач з `app/layouts` → він переїхав у
  `features/language`, бо сторінка не може імпортувати `app`; шапки беруть його звідти ж.
- **`Countdown`.** Плитка «чекаємо N с» → `Countdown` переїхав з `pages/jobs/ui` у
  `features/upload/ui`, і його показують і слайд `/jobs`, і `UploadTile`: сторінка не імпортує
  сторінку.
- **`features/auth`.** Крім форм і API → ще `SignedOutGate` (перехід для того, хто вже увійшов) і
  `SessionCheckFailure` (`ErrorState` перевірки сесії), спільні для `LoginPage`, `RegisterPage` і
  `RequireAuth`; тексти — `auth.sessionCheck.*`. Інакше три копії однакової логіки.

### Бекенд

- **`name` у `POST /v1/uploads`.** Специфікація не змінювала завантаження → веб надсилає ім'я
  файлу: без нього пошук за назвою не мав би що шукати.
- **Стабільні presigned GET.** «`refetchOnFocus`, бо presigned URL мають термін дії», підпис на
  кожен запит → `presignGet` підписує від початку поточного 300-секундного вікна
  (`signingDate` вниз до межі, `expiresIn + 300`): у межах вікна URL однаковий. Інакше кожне
  опитування раз на 3 с міняло `src` картинок і відео — повторні завантаження й перезапуск
  плеєра. Посилання живе від години до 65 хвилин. Плеєр тримає перше посилання на джерело й один
  раз пробує свіже, якщо старе вже не грає.

### Медіатека й завантаження

- **Зникнення локальної плитки.** «Зникає, коли серед завантажених сторінок є asset з
  `latestJob.id === upload.jobId`» → завантаження, яке список уже показав, позначається
  (`uploadsListed`) і більше не повертається плиткою; чекаємо лише 24 найновіші (`ASSETS_PAGE_SIZE`)
  ще не показані завантаження. Без позначки плитка поверталася, щойно файл зникав зі списку
  (видалили, у файлу новіша задача, файл з'їхав з першої сторінки); а файл, старіший за
  сторінку, на першу сторінку вже не потрапить, і опитування не зупинялося б.
- **Перехід після старту завантаження.** «Веде на `/library`, якщо людина не там» → веде на
  `/library` без рядка запиту й тоді, коли людина в медіатеці з фільтрами чи пошуком: з фільтрами
  локальних плиток немає (чи підійде новий файл під фільтр, ще невідомо), і поступ, відлік
  «чекаємо N с» і створення задачі ніде не було б видно. Фільтри при цьому скидаються.
- **Тости помилок.** «Мовчить на `/library` і `/jobs`» → мовчить на `/jobs` і на `/library` без
  рядка запиту: з фільтрами локальних плиток немає, і помилку ніхто б не побачив. Помилка, що
  приходить разом з переходом у медіатеку, оцінюється за місцем, куди веде перехід
  (`headingTo` у `useUploadFailureToasts`). Пошук із самих пробілів сторінка вважає відсутнім
  фільтром, як і Gateway.
- **Фокус після «Показати ще».** «Фокус не переміщується» → після кнопки фокус переходить на першу
  плитку нової сторінки (`data-asset-id`); sentinel фокус не чіпає; якщо нова сторінка порожня і
  фокус загубився — на поле пошуку. На останній сторінці кнопка зникає, і фокус падав на `body`.
  Оголошення «Додано ще N» прив'язане до набору фільтрів: перемикання на закешований набір нічого
  не оголошує.
- **Фокус після «Скинути фільтри» і «Прибрати».** Не описано → «Скинути фільтри» ставить фокус у
  поле пошуку; «Прибрати» на плитці — на сусідню плитку або на пошук. Обидві кнопки зникають
  разом зі своїм вмістом.
- **Назва плитки.** Текст посилання починається з назви файлу, позначка «Відео» стоїть першою лише
  візуально (`order: -1`): скрінрідер чує назву, а не тип.

### Сторінка файлу

- **Живі дані.** Опитування 3 с → плюс пауза на `Retry-After` після `429` / `503`, як у медіатеці.
- **Стани.** «`404` — `EmptyState`» → `400` (хибний id) теж «Файл не знайдено»; у стані «не
  знайдено» й помилки сторінка має `h1` «Файл».
- **Видалення.** «`isBusy` під час запиту» → поки `DELETE` у дорозі, діалог не закривається ні Esc,
  ні фоном, ні ×, а «Скасувати» зайнята; після відповіді тост показується завжди, а перехід у
  медіатеку — лише якщо людина ще на сторінці файлу. Інакше закритий діалог губив відповідь, а
  пізній перехід забирав людину зі сторінки, куди вона пішла.
- **`Dialog`.** Примітив отримав `dismissible?: boolean` (за замовчуванням `true`): з `false` Esc,
  фон і × не закривають діалог, а примусове закриття браузером відкриває його знову. Ним же
  користується діалог відкликання ключа.
- **Стан після видалення деінде.** Якщо повторний запит файлу (фокус, опитування) повертає `404` /
  `400`, сторінка показує «Файл не знайдено» замість старих даних з кешу.

### Вхід і налаштування

- **Перехід з `/login` і `/register`.** «Користувач, що вже увійшов, одразу йде…» → лише коли
  `getMe` має дані й не в помилці: після того як сесія сплила, у кеші лишаються старі дані, і
  перевірка лише `data` ганяла між `/login` і захищеною сторінкою.
- **Слухач стора.** На `login` / `register` — «скидає кеш API» → ще й очищує список завантажень, як
  на `signedOut`: завантаження попереднього користувача не мають бачитись новому.
- **Відлік `429`.** Текст «Спробуйте через N с» оголошується один раз з початковим значенням;
  видимий відлік — `aria-hidden`, щоб скрінрідер не читав його щосекунди.
- **Показ ключа один раз.** Ключ показується в діалозі → і прибирається з кешу RTK Query одразу
  після відповіді (`request.reset()`), щоб не лишатися в сторі. Після відкликання фокус — на
  заголовку «API-ключі». Redux DevTools увімкнено лише в dev-збірці: журнал дій тримав би ключ.
- **Діалог нового ключа і фон.** Діалог закривався й кліком по фону → `Dialog` отримав
  `closeOnBackdrop?: boolean` (за замовчуванням `true`), діалог нового ключа передає `false`:
  випадковий клік чи виділення тексту, відпущене за рамкою, знищували б єдину копію ключа. Esc,
  × і «Готово» закривають його, як і раніше.
- **Текст відкликання.** «Перестануть працювати одразу» → «протягом хвилини»: Gateway кешує ключі
  на 60 с (`API_KEY_CACHE_TTL_MS`).

### Тексти, токени, інструменти

- **Тексти.** `library.more.retry` не з'явився: усі повтори — новий спільний `shell.retry`. У
  підказці й ліміті ключів — `{{max}}` замість `{{count}}`: це не множина.
- **Токени.** План згадував токени, яких немає, → взято наявні: `--focus-ring` → `3px solid
var(--focus)`, `--paper-deep` → `--film` / `--table`, `--paper` → `--mount`,
  `--tone-danger-ink` → `--red`, `--text-md` → `--text-base`. Нових токенів не додано.
- **Інструменти.** `.superpowers/**` додано в ігнор eslint і prettier: робочі нотатки не входять у
  репозиторій.
